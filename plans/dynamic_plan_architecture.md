# Dynamic Goal & Plan Architecture (The Hackathon Pivot)

Your strategy is brilliant. By chaining the existing **Interview** directly into the **Plan Generator**, we create a seamless, closed-loop AI agent. 

Here is how we will architect the core "Intelligent Planning" requirement:

## 1. The Flow (Interview -> Plan -> Content)

1. **The Interview Phase:** The user chats with the AI (via text or voice proxy). The AI acts as an intake counselor: *"What are you trying to learn? How much time do you have each week? What's your current skill level?"*
2. **The Extraction Trigger:** Once the user says *"I'm ready to start"*, the Flutter app calls a new backend endpoint: `POST /api/orchestration/planner/generate/{threadId}`.
3. **The LLM Parser:** The backend grabs the entire interview chat history and sends it to a new `PlanGenerationPipeline`. 
4. **The Agentic Tool Calling (True Web Grounding):** 
   - Instead of a static catalog, we equip Gemini with a `@Tool` called `YouTubeSearchTool`. 
   - Gemini reasons about the syllabus and autonomously searches the internet in real-time to find real, verified videos that fit the time constraints.
5. **The Output:** Gemini returns a strictly formatted JSON object containing `Milestones` and `Tasks`. We save these to the database.

---

## 2. The Database Schema

We will use PostgreSQL's native `JSONB` support to avoid writing 5 separate tables and complex relational mapping. This allows extreme read/write speeds for the UI.

*   **`LearningPlan`**: `id` (UUID), `userId` (UUID), `goalStatement` (String), `planData` (JSONB).

**The JSONB `planData` Structure:**
To satisfy the Problem Statement's requirement for "Time spent vs. planned time" and "Upcoming deadlines", the JSON tree will contain:
*   `milestones`: Array of milestones.
*   `tasks`: Inside each milestone, tasks will have:
    *   `title` and `resourceUrl`
    *   `estimatedMinutes` (Planned time)
    *   `actualTimeSpentMinutes` (Actual time, updated by Flutter)
    *   `deadlineDate` (Used to trigger reschedule if they fall behind)
    *   `isCompleted`

*(Note: The `User` entity will be updated to store `totalPoints`, `currentStreak`, and `lastActiveDate` for gamification tracking).*

---

## 3. The Active Feedback Loop (Adaptation)

To hit the "Adaptability" and "Feedback Loop" requirement:
When a user finishes a Flashcard Review or completes a Task, if they score poorly, the Flutter app calls `POST /api/orchestration/planner/{planId}/adapt`. 
The AI reviews their weak points and dynamically inserts a new **Remedial Task** into their current Milestone.

## 5. Assessments & Active Feedback Extension

To fully prove the "Active Feedback Loop", we extend beyond standard Flashcards to true Assessments.

**1. MCQs and Subjective Generation:**
*   `POST /api/orchestration/assessments/generate`
*   The AI will generate both Multiple-Choice Quizzes (MCQs) and Subjective/Descriptive Questions based on the learning material.
*   *Entities:* `Assessment` and `QuizQuestion` (stored in PostgreSQL).

**2. The Subjective AI Grader:**
*   `POST /api/orchestration/assessments/evaluate`
*   The user submits a typed answer to a descriptive question.
*   Gemini grades the answer against a strict rubric, returning a JSON evaluation: `{ "score": 65, "feedback": "...", "passed": false }`.

**3. The Plan Adaptation Trigger:**
*   If the Grader returns `passed: false` (or if an MCQ score drops below 50%), the Flutter app immediately triggers the `POST /api/orchestration/planner/{planId}/adapt` endpoint.
*   The system dynamically injects a new **`[Remedial]`** task into the user's current milestone, closing the loop.

---

## 6. Stateless Gamification (Dashboard & Motivation)

To support the Dashboard and Arcade-style motivation without over-engineering relational databases:
*   **Stateless Generation:** Quizzes and Subjective Questions are generated by the LLM and passed directly to Flutter. They are *never* saved in PostgreSQL.
*   **The Gamification Endpoint:** When a user completes a task or passes a quiz, Flutter calls `POST /api/orchestration/gamification/award`.
*   **The Calculation:** The backend updates the `User` entity's `totalPoints`, checks if the `lastActiveDate` warrants a streak bump, and saves the user.
*   **The Result:** The UI can query the user profile to render rich dashboards, fire icons, and badges using hard numbers without complex SQL aggregations.

---

## 7. JSON Fragility Mitigation (LangChain4j AiServices)

To eliminate the risk of the LLM returning malformed JSON (which would crash the parser):
*   We use LangChain4j's `@AiService` abstraction.
*   We define the return type of the Agent strictly as the `LearningPlan.PlanData` Java object.
*   LangChain4j automatically extracts the JSON schema from the POJO, forces Gemini into Structured Output Mode, and seamlessly deserializes the response into strongly-typed Java objects. No manual string parsing required.
