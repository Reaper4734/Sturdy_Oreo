## 1. Module Responsibility

This module is the **dynamic visualization engine** inside the Learning Lab (Screen 05, left pane). It receives structured payloads from the Java backend (generated by the AI Orchestration layer) and renders them as interactive diagrams, annotated images, flowcharts, or server-driven widget trees — all in real-time.

This is what makes the platform feel "agentic." The AI does not just *talk* — it *draws*.

## 3. The Payload Contract (What the Backend Sends)

When the student asks a question (via M4 Chat) or when the backend decides to push an explanation, the Java backend sends a **Canvas Payload** over the WebSocket channel `/topic/session/{id}/canvas-render`.

The payload is a discriminated union. The `type` field determines which renderer activates:

### Type A: SVG Diagram
```json
{
  "type": "svg",
  "content": "<svg xmlns='http://www.w3.org/2000/svg' viewBox='0 0 400 300'>...</svg>",
  "caption": "How a WebSocket handshake works"
}
```
**When used**: Architecture diagrams, protocol flows, data structure visualizations.
**Renderer**: `svg_renderer.dart` using the `flutter_svg` package to parse and render the XML string.

### Type B: Node-Edge Graph (Interactive)
```json
{
  "type": "node_graph",
  "caption": "React Component Lifecycle",
  "nodes": [
    { "id": "n1", "label": "Constructor", "x": 50, "y": 50, "style": "neon-purple", "metadata": { "detail": "Called once when..." } },
    { "id": "n2", "label": "render()", "x": 200, "y": 50, "style": "neon-cyan", "metadata": { "detail": "Returns JSX..." } },
    { "id": "n3", "label": "componentDidMount", "x": 200, "y": 180, "style": "neon-green", "metadata": { "detail": "Runs after..." } }
  ],
  "edges": [
    { "from": "n1", "to": "n2", "label": "initializes", "animated": true },
    { "from": "n2", "to": "n3", "label": "after first paint", "animated": false }
  ]
}
```
**When used**: Concept maps, code flow diagrams, system interaction maps — anything where the student should be able to *tap a node* to learn more.
**Renderer**: `node_graph_renderer.dart` using `CustomPainter`.

### Type C: Remote Widget Layout (Server-Driven UI)
```json
{
  "type": "remote_ui",
  "caption": "Quick Comparison",
  "layout": {
    "widget": "Column",
    "children": [
      { "widget": "Text", "props": { "text": "useState vs useReducer", "style": "heading" } },
      {
        "widget": "Row",
        "children": [
          { "widget": "Card", "props": { "title": "useState", "body": "Simple state...", "glow": "cyan" } },
          { "widget": "Card", "props": { "title": "useReducer", "body": "Complex state...", "glow": "purple" } }
        ]
      }
    ]
  }
}
```
**When used**: Comparison tables, step-by-step tutorials, mixed-content explanations.
**Renderer**: `remote_widget_renderer.dart` using Flutter's `rfw` package or a custom JSON-to-Widget mapper.

### Type D: Markdown + Mermaid
```json
{
  "type": "markdown",
  "content": "## The Event Loop\n\nJavaScript uses a single-threaded event loop:\n\n```mermaid\ngraph LR\n  A[Call Stack] --> B[Web APIs]\n  B --> C[Callback Queue]\n  C --> A\n```\n\nWhen the call stack is empty, the event loop picks the next callback."
}
```
**When used**: Text-heavy explanations with embedded diagrams for textual learners.
**Renderer**: `markdown_renderer.dart` using `flutter_markdown` with a custom Mermaid block builder.

### Type E: Annotated Image
```json
{
  "type": "annotated_image",
  "image_url": "https://cdn.example.com/react-devtools-screenshot.png",
  "caption": "React DevTools Components Panel",
  "annotations": [
    { "x": 120, "y": 45, "width": 200, "height": 30, "label": "Component Tree", "color": "cyan" },
    { "x": 120, "y": 190, "width": 200, "height": 80, "label": "Props Inspector", "color": "purple" }
  ]
}
```
**When used**: Explaining screenshots, tool interfaces, or visual references.
**Renderer**: `image_annotation_renderer.dart` — overlays colored rectangles and labels on the loaded image.

### Type F: Code Playground (Interactive Code Editor)
```json
{
  "type": "code_playground",
  "language": "javascript",
  "caption": "Try fixing the memory leak in this useEffect hook",
  "initial_code": "function Timer() {\n  const [seconds, setSeconds] = useState(0);\n  useEffect(() => {\n    setInterval(() => setSeconds(s => s + 1), 1000);\n    // TODO: Add cleanup function here\n  }, []);\n  return <h1>{seconds}s</h1>;\n}",
  "instructions": "Add a return () => clearInterval(...) function inside useEffect.",
  "expected_output_contains": "clearInterval"
}
```
**When used**: Hands-on coding exercises, interactive bug fixing, code experiments.
**Renderer**: `code_playground_renderer.dart` using `code_text_field` (or Monaco WebView) + execution evaluator (JS web worker / Dart sandbox). Features "Run Code", "Check Solution", and "Ask AI Mentor for Hint" buttons.

- **Execution Isolation & Security (L21 Fix)**: Client-side JavaScript/HTML executes inside an isolated **Web Worker** with zero DOM/cookie access and a hard 2-second execution timeout. Non-JS languages (Python/C++) execute via sandboxed backend containers (Judge0 API with 512MB RAM cap and disabled networking).
- **Editor Focus Mode (UX21 Fix)**: Includes a "Expand Editor (85% Width)" button in the playground header. Tapping it expands the code editor panel across 85% of the screen while collapsing the Mentor Chat to a narrow side drawer, providing ample room for coding on smaller displays.

### 3g. Diagram Persistence & Export (UX14 Fix)

- **Save Diagram to Notes**: Every canvas renderer header includes a `"📌 Save Diagram"` button. Tapping it calls `POST /api/diagrams/save`, storing the JSON payload in `saved_diagrams` (M8) linked to the user's active node. Saved diagrams appear in the Resource Map (Screen 06).
- **PNG / Image Export**: Includes a `"📷 Export PNG"` button. Uses Flutter's `RenderRepaintBoundary.toImage()` to capture the canvas view as a high-resolution PNG image for local download.

## 4. Rendering Pipeline (How a Payload Becomes Pixels)

```
Step 1: WebSocket message arrives on /topic/session/{id}/canvas-render
         ↓
Step 2: websocket_service.dart parses the raw JSON
         ↓
Step 3: canvas_payload.dart factory deserializes into the correct union variant
         (CanvasPayload.svg / CanvasPayload.nodeGraph / etc.)
         ↓
Step 4: canvas_state_provider.dart updates its state with the new payload
         ↓
Step 5: sandbox_canvas.dart rebuilds — reads the payload type and switches:
         switch (payload.type) {
           case svg       → SvgRenderer(payload)
           case nodeGraph  → NodeGraphRenderer(payload)
           case remoteUi   → RemoteWidgetRenderer(payload)
           case markdown   → MarkdownRenderer(payload)
           case annotatedImage → ImageAnnotationRenderer(payload)
         }
         ↓
Step 6: The selected renderer widget draws the content on screen
         ↓
Step 7: If interactive (nodeGraph), tap_handler.dart performs hit-testing
         and highlight_dispatcher.dart sends tapped metadata to the Chat via WS
```

## 5. Node Graph Custom Painting (Deep Dive)

This is the most complex renderer. Here is how it works:

### 5a. The Canvas Coordinate System

The `NodeGraphRenderer` wraps a `CustomPaint` widget inside an `InteractiveViewer` (for pan & zoom). The `CustomPainter` receives the list of `GraphNode` and `GraphEdge` objects.

### 5b. Drawing Nodes

For each node:
1. Draw a **rounded rectangle** at `(node.x, node.y)` with dimensions based on text measurement.
2. Apply the **glow shadow** matching `node.style`:
   - `neon-purple` → `BoxShadow(color: accentPurple, blurRadius: 15)`
   - `neon-cyan` → `BoxShadow(color: accentCyan, blurRadius: 15)`
   - `neon-green` → `BoxShadow(color: accentGreen, blurRadius: 15)`
3. Fill with the glassmorphic `bgCard` color.
4. Draw the `node.label` text centered inside using the Outfit font.

### 5c. Drawing Edges

For each edge:
1. Compute the start point (center-bottom of `from` node) and end point (center-top of `to` node).
2. Draw a **bezier curve** between them using `canvas.drawPath()`.
3. Draw an **arrowhead** at the end point.
4. If `edge.animated == true`, use an `AnimationController` to animate a **dashed line** flowing along the path (a marching-ants effect using `PathMetrics` and `dashOffset`).
5. Draw the `edge.label` text at the midpoint of the curve.

### 5d. Hit Testing (Tap Interaction)

When the student taps the canvas:
1. `tap_handler.dart` receives the tap position (adjusted for current pan/zoom transform).
2. It iterates through all nodes, checking if the tap falls within the bounding rect of any node.
3. If a hit is found:
   - The `canvas_interaction_provider` updates with the selected node's `id` and `metadata`.
   - The `NodeGraphRenderer` repaints with the selected node highlighted (thicker border, brighter glow).
   - The `highlight_dispatcher` sends a WebSocket message to the backend:
     ```json
     {
       "event": "canvas_node_selected",
       "nodeId": "n2",
       "label": "render()",
       "metadata": { "detail": "Returns JSX..." }
     }
     ```
   - The AI Mentor chat (M4) receives this context and can respond: *"I see you highlighted `render()`. Here is how it connects to the virtual DOM..."*

## 6. Animated Transitions Between Payloads

When a new payload arrives (replacing the previous one):
1. The current canvas content **fades out** (200ms).
2. A brief **loading shimmer** plays (150ms) — a translucent wave effect across the canvas area.
3. The new content **fades in** (300ms).

This prevents jarring content swaps and gives the AI a "deliberate" feel.

## 7. Adaptive Behavior Based on Persona

The `render_mode` from M1's `RenderModeProvider` influences M2:

| render_mode | Canvas Behavior |
| :--- | :--- |
| `visual` | Backend is prompted to generate `node_graph` or `svg` payloads. Canvas is the primary content area (takes 60% width). |
| `textual` | Backend is prompted to generate `markdown` payloads. Canvas shrinks to 40% width; the markdown panel gets more space. |

The backend's AI Orchestration layer (M6) uses the persona's `visualization` score to decide which payload type to request from the LLM.

## 8. Integration Points

| Touches Module | How |
| :--- | :--- |
| **M1 (UI Shell)** | M1 provides the `adaptive_canvas_panel` container in Screen 05. M2's `SandboxCanvas` widget is placed inside it. M1 also provides the `RenderModeProvider` that M2 reads for adaptive sizing. |
| **M4 (Chat Interface)** | Bidirectional. M2 sends `canvas_node_selected` events to M4's chat context. M4 can trigger new canvas renders by forwarding the student's question to the backend. |
| **M5 (Java Core Engine)** | M2 subscribes to the WebSocket channel `/topic/session/{id}/canvas-render` for incoming payloads. M2 publishes `canvas_node_selected` events back to `/app/session/{id}/canvas-interaction`. |
| **M6 (AI Orchestration)** | M6 decides *what* to render and generates the structured JSON payload. M2 is purely a renderer — it does not call the LLM directly. |
